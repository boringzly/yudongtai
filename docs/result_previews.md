# 变化检测与分类：抽样质检预览

分类完成后自动生成，单图和文件夹批量任务均适用。`previews` 与 `logs`
统一放在 **最终输出目录之外**，避免成果入库程序把辅助目录误当作成果。
变化检测主进程、GPU 子进程、分类及其错误报告使用同一位置规则。
日志会打印日志文件和预览总览页的完整路径，例如：

```text
/share/ib/3/332/
├── output/6978/out/                 # 最终成果位置不变
│   └── classification_result.shp    # 及其配套文件
└── task_diagnostics/6978/           # 不在 output 目录内
    ├── logs/
    │   ├── change_detection.log
    │   ├── change_detection_gpu_1.log
    │   ├── classification.log
    │   └── classification_summary.json
    └── previews/
        ├── index.html
        ├── manifest.json
        └── sample_001.jpg
```

优先通过工作流的 `PATH_OUTPUT`（兼容 `path_output`、`DATA_OUTPUT_DIR`）定位任务；
没有这些环境变量时从 `working`、`output/<任务号>` 或末级 `out` 推导。
可复制整个 `previews` 文件夹到电脑，双击 `index.html` 离线查看，也可以直接打开 JPG。
不改变工作流的矢量结果发布协议，也不把辅助文件登记进成果数据集。

如需指定其他共享盘位置，给两个步骤设置相同的绝对路径，例如
`CD_ARTIFACTS_ROOT=/share/algorithm_diagnostics`，程序会自动创建
`<任务名>-<路径摘要>/logs` 和 `previews`，避免不同任务互相覆盖。
指定位置须可写，不能位于任务输出树中；程序不会为了写日志而回落到成果目录。
更新时须包含仓库根目录新增的 `task_artifacts.py`。

**已有任务的旧 `logs` / `previews` 不会被自动删除或搬走。** 如果要复用旧结果目录
重试入库，需要先把其中辅助目录移到独立诊断位置，保留历史日志；新任务会直接写新位置。

## 每张九宫格的内容

| 前时相原图 | 后时相原图 | 后时相叠加变化边界 |
| --- | --- | --- |
| 前时相六大类像元分类叠加 | 后时相六大类像元分类叠加 | 后时相叠加变化区域 |
| 最终图斑的前时相类别 | 最终图斑的后时相类别 | 图斑 UID、类别转换、坐标、图例 |

每张图只标出**一个被抽中的图斑**，不是该窗口内所有变化图斑。面边界和孔洞来自
真实结果几何，细长道路不会用外接矩形填充。所有面板使用同一范围、同一显示网格；
不同坐标系先对齐，类别图使用最近邻重采样。8-bit 原图保留 RGB 色彩，
其他位深的原图前后采用统一的 2%–98% 拉伸，避免分别拉伸制造假的颜色变化。

像元分类颜色采用算法的同一份 14→6 类映射；最终图斑类别直接读取 SHP 的
`pre_code` / `curr_code`，不会在缩略图上重新投票。批量模式使用成功参与最终合并的
单组 SHP 和其对应影像，避免合并后 UID 重复导致匹配错图。

`0=未知、1=耕地、2=林地、3=草地、4=水域、5=建设用地、6=未利用土地`。
未知像元不涂色，原图无数据区域显示深色。前后类别相同仍会抽样，不把它当成“无变化”。

## 数量、空间与开关

- 默认每个**任务**最多 30 张（不是每对影像 30 张）。不足 30 个图斑就按实际数量输出。
- 按影像对和前后类别转换分组抽样，固定种子，尽量覆盖不同情况。
  这是便于检查问题的分层样本，**不能用图片中的类别频率估算总体面积或分类精度**。
- 单张 1504×1762 JPG，质量 85；所有 JPG 合计最多 50 MiB。达到上限即停止。
- 只读取抽样窗口，输出统一缩小至 480×480 的面板；不额外保存小瓦片、裁剪 TIFF、PNG。
  对于覆盖整幅影像的大图斑，窗口仍可能较大，但输出和处理缓存有上限。
- 相同目录重新运行会清理上一次清单登记的抽样 JPG，避免积累或误看旧图；不删除其他文件。
- `CLASSIFICATION_PREVIEW_COUNT=20` 可调整张数，`0` 关闭，硬上限 60。
  无变化图斑时仅保存说明页和清单，不造出空白“检测结果图”。

这些是分类进程的环境变量，现有工作流不修改也会默认生成。可选
`CLASSIFICATION_PREVIEW_FONT=/path/to/NotoSansCJK-Regular.ttc` 指定中文字体；
自动查找 Noto CJK、文泉驿及 Windows 中文字体。缺少字体时图内改用英文标签，
HTML 和 JSON 仍记录中文类别，避免出现方框乱码。

## 可追溯与容错

`manifest.json` 记录来源影像、分类 TIFF、单组 SHP、FID/UID、类别、CRS 和显示范围。
单图模式的分类 TIFF 后续仍会按原逻辑清理，清单中的临时 TIFF 路径仅用于追溯。
预览阶段向日志和 Kafka 发送进度，流程诊断 JSON 保存预览摘要；另外输出
`preview_index`、`preview_count` 两个 swap 变量。

预览依赖现有环境的 rasterio、Fiona、NumPy、Pillow，不调用 GPU、不重新推理。
缺依赖、缺文件、坐标异常或写入失败均只记录预览告警，**不会将有效的 SHP 任务变为失败**。
输入读取仍受存储速度影响；任务被强制终止、SHP 尚未成功生成时不会保证有预览。

## 验证

```text
python -B -m unittest discover -s tests -p "test_*.py"
```

`test_result_previews.py` 包含真实合成 TIFF / SHP 的渲染、CRS 对齐、NoData、
道路孔洞、六大类配色、抽样数量、磁盘上限和重跑清理测试。无 GIS 依赖的环境会
明确跳过 GIS 集成测试，其余测试无需 GPU。
